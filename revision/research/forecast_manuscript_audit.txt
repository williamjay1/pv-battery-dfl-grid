P2-A: StoreNet aggregation is not a 30/30 completeness rule.
Location: article_full.txt Methods 2.8, approximately line 99: 'We aggregate only complete half-hours'.
Executed rule: reject invalid/negative/duplicate/off-minute records jointly; retain half-hour bins containing at least 27 distinct jointly valid GC/PV minutes; average the available power observations. All 48 retained bins are then required for a target day and each of its seven history days. This is a sampled-power mean, not interval-integrated revenue metering.
Replace with: 'We retain a half-hour only when at least 27 of its 30 minute records have valid consumption and production measurements, and take their arithmetic means without interpolation. Target and history days require all 48 retained half-hours.'
Evidence: research/storenet_external_protocol.json half_hour_aggregation; research/prepare_storenet_external.py lines 46-57. The 3,439 complete target days and 2,224 scored household-days are correct under this 90% coverage rule.

P2-B: Identify the single-seed main economic evidence before stating three-seed inference.
Location: article_full.txt Methods 2.6, approximately line 85, opening 'Primary contrasts average paired daily differences across three seeds...'.
The Abstract, Table 2, Fig.1 and all299 headline 1.131 cents use seed11 only. The original nine deployment cells and the external three-seed summary use averaging across seeds. The later sentence distinguishes fixed-model extensions, but the unqualified first sentence can make the headline appear replicated across three seeds.
Suggested replacement: 'The original nine deployment-cell contrasts and the StoreNet seed-mean transfer estimates average paired daily differences across three seeds before calendar-block resampling. The expanded private comparison, practical alternatives and new controller/input/wear comparisons use seed 11; their intervals describe temporal uncertainty for that fitted model.'
Do not change any numbers or add experiments.

P2-C: Resource memory and timing scope require explicit labels.
Locations: Methods2.4 timing paragraph; article Table3 header 'Process memory (MB)' and note; Results3.2 'Deterministic schedules take about1.5ms'.
The listed 618/808/619/618 MB are replay/solver-benchmark process peaks, not peak learning memory. Learning peaks are separately 854.8/936.2/938.8 MB for continuedMSE/calibration/DFL. TableS3 correctly separates them. Relabel the main column 'Replay RSS (MB)' and reference TableS3 for learning RSS.
Timing code measures QP RHS update+solve, excluding feature construction, neural/HGB prediction and data import. Specify 'QP solves take...' and add that exclusion to the caption, so these are not advertised as end-to-end control latency. The 1,024 pairs/20warmups/3repetitions characterize the solve benchmark. Learning uses4096/1024 pairs for MSE/DFL and2048/2048 for calibration, which S2 already reports.
Only the method benchmark subprocesses were serial relative to each other; multiple learning jobs did run concurrently. Narrow 'Training and scheduling times are measured in serial...' to 'Scheduling benchmarks run in serial single-thread method subprocesses; incremental learning also uses one numerical thread per process. Unrelated jobs run concurrently.' Existing concurrent-work caution is correct and should remain.

P2-D: Predictive RMSE citation is an old signed, known-household diagnostic.

P2-E: Identify the forecasting backbone of practical calibration/scenario methods.
Location: main Methods2.4 first calibration paragraph and scenario paragraph. SupplementS2 says 'original frozen forecast backbone', but the distinction should be explicit in the main comparison.
Suggested sentence: 'Calibration and residual-scenario control both start from the frozen seed11 supervised PV model with the common HGB load predictor; continued MSE and DFL are separate matched continuations of that warm-start.' This prevents attributing SAA/calibration to the continued-MSE weights or implying all practical alternatives have identical training budgets. The manuscript otherwise correctly separates objective attribution from engineering-method comparison.
